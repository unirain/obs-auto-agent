# Reading Agent implementation guidance

## Authority and scope

Read `intent.md`, `docs/specs/reading-agent-spec.md` and `docs/plans/README.md` before changing behavior. User instructions take precedence. Preserve observe_only model costs, no article or pending PR count cap, the shared 50 GB storage bound, human PR merging, and production/preview separation.

## Implementation and verification

- Use TypeScript ESM, npm with a committed lockfile, strict type checking and Vitest. Pin dependencies; verify SDK behavior against installed declarations or official documentation.
- Keep side effects behind typed adapters. Model tools never receive OSS, GitHub or model API secrets. Source text never becomes executable configuration.
- A committed checkpoint is required before paid calls or remote writes. Unknown results require reconciliation; never treat unknown as absent or zero.
- Restore only a validated consecutive immutable commit chain. Never delete commits, skip sequence numbers or silently initialize after an error.
- Scope and deployment targets come from trusted configuration. Preview never receives production write capabilities and never becomes production.
- Tests must assert persistent state and external effects, including the next run after failure. A fake test does not prove live OSS, SDK, RAM or GitHub behavior.
- Real integrations use explicit isolated test resources. Production cron stays disabled until the G5 evidence is complete. Do not create cloud resources or expose credentials to obtain a green test.

## Coordination and task records

`docs/tasks/implementation.md` is the canonical work-package/gate status. `docs/notes/implementation-log.md` records decisions, results and blockers. Update both when work changes authoritative state; distinguish implemented, local_verified, live_unverified, blocked_external and complete.

Parallel workers edit only assigned module paths. Shared contracts belong to the storage worker until handed off; package/config files and integration entrypoints belong to the coordinating worker. Coordinate contract changes before consumers change them. Do not discard another worker's edits.

Before reporting completion, run the applicable typecheck, tests and build, inspect plan-to-test coverage and record evidence. All 25 work packages, G0–G5 and live quality checks remain in scope even if external setup is missing. Keep this file synchronized with actual commands and module boundaries as implementation develops.

## Commands and module boundaries

- Node 24; `npm ci`, `npm run typecheck`, `npm test`, `npm run build`, and `npm run coverage:spec` verify the local implementation. `npm run test:live` selects explicitly gated integrations; skipped tests are not evidence.
- `agents/reading/src/app` composes the trusted host controller, journal, bootstrap and maintenance. Storage/workspace/contracts define persistent state; runtime/stages/tools/policy own restricted model capabilities; publish/monitor/config own external delivery and operations.
- The implementation repository is `unirain/obs-auto-agent`. Resolve its default branch from GitHub metadata or local `origin/HEAD`; do not assume `main`. Preserve the initial Apache License.
- Production generation cron remains disabled. Before any public commit, scan tracked candidates for actual locally available credentials without printing their values. Keep private test outputs in ignored `.reading-local/`.
- Human management uses `inspect` and `recover`; recovery is never a model tool. Require reason, evidence reference, actor and exact revision. Preserve counters and unknown financial facts; a retry of an unknown call requires explicit acknowledgement and a fixed pending input.
- Explicit `new_generation` requires changed operator input and an archived prior revision; preserve source classification allowances and all prior charges. Production requires complete readonly GitHub readiness. `record_feedback` verifies actual PR facts and commits feedback with the management audit atomically.
- Project control rows store immutable source-body references; model reading loads verified bodies on demand with bounded cache/ranges. Bind real SDK/native binary and tool image hashes; unavailable fixed inputs stop the affected project rather than silently switching versions.
- Host checkpoints validate previous and next project state; new generations preserve invocation facts and archive the previous version. Nonlocal generation requires the shared writer mutex. SIGINT/SIGTERM stop SDK queries and preserve uncertain outcomes for reconciliation.
- Skill cloud mode requires its exact versioned contract and three matching documentation markers. Writing and independent image review use registered resources; keyword detection or a prior writing visual receipt is insufficient. Local or remote draft proposal commits are not published target-library default-branch versions.
- Every persistent reservation/upload/delivery envelope declares schema version 1; reject unknown/unversioned rows rather than silently defaulting. Cleanup uses a separate image deletion identity and current host scope/prefix permission, with complete remote references and exact version readback.
- Usage summaries cover whole queries, including late steps; never sum a query summary and its steps. Persist Beijing start-day/project/run attribution and keep missing metadata or billing observations unknown.
- Public schema definitions come from exported document tables; `npx tsx agents/reading/evals/generate-schemas.ts --check` verifies all 40 documents. Regenerate explicitly after contract changes. Parse stored UTC without normalizing malformed legacy facts; seconds and millisecond Z instants are supported.
- Run reports retain configured input commit, actual or unavailable implementation/project versions, committed policy references and all usage observation fields. Local cross-module replay proves contract interoperability only; G0 passing does not authorize paid/live integration before G1.
- Per-case acceptance audits name actual test assertions and remaining layers. Local covered is not full completion; preserve missing local scenarios and never infer them from green files. Quality freeze binds human labels, splits, note exclusions and source body hashes; result measurements must match that frozen corpus. Use `evals/quality/run.ts` inspect/versions/freeze/execute/merge/report. Only execute invokes the actual host, requiring complete G1 and a published notes default-branch skill commit; replay is explicitly local. Frozen primary bodies and versions bind the preview session; never expose human labels or heldout notes to model context. Interrupted attempts without final reports retain unknown duration and usage.
- Source gap management uses inspect-source-gaps/manage-source-gap with host identity, reason, evidence, exact revision and gap hash. Health/event/audit commit atomically with revision checked inside the writer queue. It accepts missing coverage only; ordinary Issue comments and a validated_fill boolean are not backfill proof. verify-source-backfill reads committed source/run reference hashes, ranges and fixed-revision scope; current adapters have no completeness contract, so it returns unverified/can_fill=false and never closes a gap. Diagnostics are snapshot-bound and do not imply current remote HEAD.
- Rendering commits checked input/SVG/receipt before PNG export. Cold reuse binds input, skill, image manifest and source hashes; incomplete/drifted receipts fail. A restored checked source never authorizes another unknown model query. Docker fault fixtures are local process/persistence evidence only.
- Collection continues a page chain only for successful/partial reads; disabled/not_attempted/failed results stop that source and preserve its cursor. Candidates, progress, result and health share a checkpoint. A readonly monitor must see committed recovery before closing a source Issue; raw successful HTTP/parsed data is insufficient.
- Recheck latest execution/semantic policy after asynchronous SDK admission and before preparing a query. Bind known delivery facts to production/project/generation/delivery identity, and preserve the confirmed PR number when synchronizing candidate state and manual receipt feedback.
- Active query refresh must invalidate a changed fixed semantic hash as well as execution permission. Recheck the generation cutoff after asynchronous policy persistence. Nonterminal SDK errors return request_unknown with their cause; aborts preserve unknown usage and immediate manual reconciliation, never automatic replacement queries.
- Join already-started active policy refresh checkpoints before an executor returns or its writer is handed to recovery; stopping the timer alone leaves a stale-HEAD race with cold restore.
- Knowledge recall treats current default-branch and actual pending PR bytes as authoritative. Closed/merged workspace drafts are historical and cannot become recalled knowledge; a pending remote note also supersedes its old local draft. Reconcile existing PRs before freshness/classification decisions, including after receipt loss beyond 24 hours.
- Same-intent concurrency proof compares the exact serialized commit bytes at the immutable store boundary, not two independently generated UUID manifests. GC verification compares all commit keys/hashes and cold-reads protected historical chunks. Unknown delivery cleanup evidence must run the same delivery through maintenance with current incomplete remote references.
- Local Vitest suite uses four workers; its 61-candidate, full preview cold-recovery and material-chain persistent I/O scenarios have a 60-second test budget, not a product SLA. Verification fingerprints include vitest.config.ts as execution configuration. Policy fixtures own their state per fixture; global shared test objects must not hide suppression/resume effects.
- Host secret guards scan known credentials and common private-key/token forms before checkpoint, restored materialization/read, delivery and image effects. Values stay in a host closure; constant errors never reveal matches. Do not silently redact or rewrite immutable facts. Browser profile/cache/storage paths are excluded. Unknown/obfuscated/hidden secrets still require isolation; see docs/runbooks/sensitive-content.md.

- Confirmed writing results with blocked visual checks remain manual across cold runs; keep the original reason, receipts and counters instead of silently reusing a cached result after resetting activity. New run reports disclose image degradations with project/generation/context identity; legacy version-1 reports may omit this field, never infer an absent legacy observation.

- The trusted Actions host Publisher independently validates delivery targets before intents or Git writes; malicious workflow/traversal/hidden/symlink inputs must preserve state and have zero effects after cold restore. The spec does not require inventing a separate validator job. Full material/intake/fixed-policy replay is local evidence, not native service or semantic/human quality proof.

- Mirror admission ignores the current candidate's own alias before checking the body-hash owner; preserve the duplicate explanation, prior files and charges. Current knowledge recall reloads committed same-generation/context project metadata so a just-read title participates, while fixed examples/skills/prompts remain bound.

- Writing/review batch continuation requires a successful typed version-1 yield bound to its exact succeeded/consumed invocation, context and revision. Preserve pending-query progress baselines across lost consumption checkpoints; partial Writing remains unsubmitted and partial Review findings survive exact-manifest continuation. SDK conversation turns and persistent tool-call budgets are separate limits; an SDK max-turn error is never a successful yield.

- OSS native transport diagnostics use host-only constructor injection, never deployment/model JSON. The probe commits a local immutable intent before cloud writes, binds code/SDK/Node hashes and suppresses authenticated TLS success before HTTP parser delivery. A post-response adapter throw is not transport-loss evidence; broad credentials never prove RAM denial.

- Quality source preparation is readonly and does not label, freeze or certify complete bodies. Unsupported video sources stay unprepared; partial snapshot sets cannot execute frozen evaluation. Note exclusion matches bind an actual target default-branch commit and still require human alias review. Reliability report counts are bounded to supplied verified evidence; missing data and unproved source completeness remain unknown.

- URL download accounting admits one logical fetch before HTTP, checkpoints each observed payload chunk including redirects, and joins started accounting on stream/browser failure. Already observed over-limit chunks remain recorded; stop subsequent hops, never clamp counters or count final bytes twice. Repository version and tree checkpoints recover independently so a fixed commit without its tree can resume listing.

- Clock fixtures supply their own environment rather than inheriting Actions READING_JOB_STARTED_AT. Verify that an expired trusted job origin overrides a fresh caller start, with zero model queries and cold-restorable initial state; preserve production clock precedence.

- Native source timeouts charge cumulative network wait across chunks while excluding awaited host accounting backpressure; the absolute project deadline remains active and joins already-started byte checkpoints. Preview cold recovery restores the exact retained tool image/archive and manifest; missing/expired fixed archives stop before model calls, never rebuild a substitute. Artifact retention is bounded and does not prove indefinite runtime availability.
