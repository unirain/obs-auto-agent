# 阅读 Agent 实施总计划

本计划将[阅读 Agent 规格](../specs/reading-agent-spec.md)拆成可以独立实现、逐步集成的工作包。先证明状态不会丢失，再用隔离预览验证阅读质量，随后接入测试交付，最后启用正式定时任务。当前正在实施，工作包和门槛状态以[实施任务](../tasks/implementation.md)及[实施日志](../notes/implementation-log.md)为准。

规划日期：2026-10-13。需求优先级为用户明确决定、[intent](../../intent.md)、spec、实施计划；计划不能自行改变前两者约定的范围。

## 当前基线与实施默认值

- 规划起点只有 `intent.md` 和 `docs/specs/reading-agent-spec.md`，没有运行代码、package manifest、workflow 或 `.git`。现已建立工程骨架；2026-10-13 用户提供实现仓库 `unirain/obs-auto-agent`，已连接其默认分支 `master`，保留原有 Apache License。独立测试交付仓库仍需另行准备。
- 采用 spec 已选的 TypeScript、Claude Agent SDK、Actions Linux 工具容器和 OSS 原生客户端。
- 工程默认用 npm、提交 `package-lock.json`，TypeScript 开启 strict，故障与契约测试使用 Vitest；Node、SDK、OSS 客户端及镜像版本在兼容性核对后固定，不使用浮动版本替代验证。
- 凭据缺失不阻止纯函数、对象存储替身、SDK 回放和 GitHub 替身开发；真实服务测试必须等待对应环境准备好。
- 金额为 `observe_only`，不设置每轮／每日模型金额上限；不增加篇数或待审 PR 门槛。50 GB 仍是正式、预览和受管图床的合计容量。
- 本次规划不创建云资源、不运行付费模型、不提交或合并 PR、不修改笔记库 skill。相关变更是后续工作包的交付物。

## 依赖顺序与通过条件

| 门槛 | 必须具备的结果 | 通过后允许的集成 |
| --- | --- | --- |
| G0 共享契约 | 工程骨架可构建，schema 与状态转换有样例；scope、身份、错误类别、接口所有者明确 | 三模块针对同一套契约并行开发，使用替身和回放 |
| G1 持久化与权限 | 本地恢复故障通过；真实私有 OSS 测试桶证明禁止覆盖创建、响应丢失对账、恢复完整性和权限拒绝；预览不能写正式前缀 | 在隔离 preview 中启用真实 SDK 和模型调用 |
| G2 单 URL 预览 | 无标签混合内容可受限分类；证据、笔记和图片完整；中断可恢复或明确转人工；预览无正式写权限 | 将已验证的阶段产物接入测试 Publisher |
| G3 隔离交付 | 测试环境的正式入队、资源上传、审校、封存、PR 创建与对账端到端通过；人工改动受保护 | 接入完整采集和运行报告，准备上线演练 |
| G4 信源与监控及质量 | 两个来源适配、覆盖缺口与逐来源告警通过；质量样本由用户确认；容量边界和暂停恢复演练完成 | 准备正式配置和一次受控手动运行 |
| G5 正式启用 | 正式资源权限检查、部署配置与默认值核对完成；正式手动链路确认，故障处理入口可用 | 启用每日定时并观察首轮实际结果 |

G0 → G1 → G2 → G3 → G4 → G5 是集成验收顺序，不要求所有代码按此顺序串行编写。信源 fixtures、Publisher 替身测试、监控事件回放都可在 G0 后并行开发；未通过对应门槛前，不提前接入真实外部写入。

第一批应完成 G0 和 G1 所需的存储最小链路，不把所有来源适配、模型提示词和图形工具一起接进故障排查。

## 共享接口与所有者

| 契约 | 主责 | 使用方与不可跨越的边界 |
| --- | --- | --- |
| 身份、scope、schema envelope、错误分类、状态转换注册 | S，A/O 共同评审 | 所有模块使用同一枚举；未知 schema 拒绝，preview 不得变更为 production |
| WorkspaceManager、WorkspaceHandle、CheckpointChange、artifact 引用 | S | A/O 提交类型化变更；Agent 不直接写 state、outputs 或 OSS |
| Invocation 持久化与 SDK 事件映射 | S 负责日志原子性，A 负责 query 生命周期 | query 前意图已提交；unknown 先对账，不能另起 query 隐式重试 |
| PolicyGate、PolicyCheck 与分类凭证 | A | S/O 消费检查回执；每个请求带能力范围，旧 manifest 回执不是当前许可 |
| Candidate、ManualSubmission、Selection、ResearchPacket、StageResult | A | S 持久化；O 的入口只解析参数，不复制选题或来源许可判断 |
| 资源计划与 ResourceManifest | A 定义本地资源需求，O 主责上传清单和回执，S 校验引用 | 正式上传由 O 完成；A 在 URL 回填后最终审校；preview 只保留相对资源 |
| DeliveryManifest、发布意图及 GitHub 回执 | O，S 共同校验封存 | S 发布有效快照，O 只读封存文件；不确定远端结果禁止建立替代交付 |
| SourceIncident、RunRecord 与监控读取视图 | A 产生来源事件，O 定义消费契约，S 原子持久化 | 事件不能只存在易失日志中；监控只读必要数据、只写实现仓库 Issue |
| 全局容量视图与本 scope 预留 | S | 正式和预览共享互斥与总额度；预览不能为了计量获得正式证据或写入权限 |

G0 时共同确定 schema 的必需字段、nullable 字段、版本、错误和至少一组合法／非法样例。接口实现可替换，但不能由各模块各自定义同名不兼容 DTO。接口变更必须同步生产方、消费方及契约测试。

## 建议的交付批次

| 批次 | 可审阅交付 | 主要验收 |
| --- | --- | --- |
| B0 工程和契约 | 根 package/lock、tsconfig、测试入口、schemas、fixtures、配置样例及秘密排除规则 | G0；无需凭据即可构建和跑契约测试 |
| B1 存储最小链路 | 初始化、blob/manifest/commit、恢复和故障注入；真实 OSS 探针及结果记录 | G1；不接模型、图床和目标笔记库写入 |
| B2 受限执行 | 最新策略、classify_only、调用意图与 usage、SDK/tool 隔离、preview 路由 | 分类、暂停、unknown 恢复和权限拒绝测试 |
| B3 阅读预览 | 证据、四阶段、Linux skill 适配、图形验证和私有预览产物 | G2；真实单 URL 能被人工检查 |
| B4 正式提交与测试发布 | 人工入队、统一去重、资源上传、审校后封存、Publisher 和回执 | G3；测试仓库重复提交只产生一个逻辑交付 |
| B5 采集与运行维护 | 两个来源、容量和 GC、watchdog、Issue 投影、质量评估 | G4；故障可见，积压可继续，质量由用户判断 |
| B6 部署与切换 | 配置、权限清单、运行手册、正式手动验证及定时开关 | G5；记录启用时间和首轮结果 |

批次是建议的提交／PR 切分，不是必须等待上一批所有代码合并才能开发的限制。每批尽量独立可测试；接口基础先合入，再合入消费者，避免长期漂移的并行实现。

## 完成定义与进度记录

每个工作包的完成记录至少包含实现 commit、对应验收 ID、执行环境、通过／失败／未执行结果，以及仍依赖的环境条件。文档已写、mock 测试通过、真实服务测试通过和用户确认质量是四种不同的事实。

涉及故障恢复的工作包必须展示失败后的持久状态和下一步动作，不能只检查日志出现某句话。涉及外部写入的工作包必须同时检查目的地实际状态、OSS 回执及下一轮行为。

当前门槛状态见[实施任务](../tasks/implementation.md)，本地代码与测试进展不代表全部真实门槛通过。首次实施从 B0 和 [存储计划](01-workspace-storage-plan.md)的工程／契约工作包开始，其他模块同步准备只读 fixtures 和接口测试。
